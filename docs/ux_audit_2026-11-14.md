# UX audit — 14 Nov 2026 (Analyst view, consolidated)

> Source: external UX review of the live site. Status values: Open / Fixed in PR# / Partially / Won't fix + reason. Update this file as prompts close items.

Reviewed 14 Nov 2026 on the live site: `/?view=analyst` (screenshots at 1280×800 and 375×812, plus DOM checks), with `/explore` and `/findings` read as page text.
Severity: **P0** = hurts trust, fix first · **P1** = noticeably looks off or blocks an analyst task · **P2** = polish.

## Verdict
It isn't over-full. An analyst can handle this much data. It's **noisy and inconsistent**: the same metadata appears again and again, two type systems compete, card contents don't line up, and some elements (the CV/LinkedIn line) don't belong in a product view. Most of the "weird" feeling comes from about six layout rules not being applied. The data itself isn't the cause.

## Six system rules that fix most of section D/E
1. **3-column grid** for hospital cards (3×3).
2. **Fixed card anatomy** with reserved slots, so numbers sit on the same baseline.
3. **One provenance line per section**; badges only when a tile differs.
4. **Type scale of 5 sizes**, with the H1 clearly larger than the H2.
5. **Spacing tokens**: 48px between sections, 16px heading→content, 12px inside cards.
6. **One naming convention** for hospitals (short code plus a tooltip).
